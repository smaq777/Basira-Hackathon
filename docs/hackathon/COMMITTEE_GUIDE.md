# Committee guide

Basirah helps Arabic Islamic-content editors distinguish an accurate quotation from an unsupported inference, using attributed source evidence and explicit abstention.

## Start with the actual application

- [Live Railway staging](https://api-staging-42bc.up.railway.app/): paste a public/synthetic Arabic draft as a guest; no provider key required.
- [Public GitHub repository](https://github.com/smaq777/Basira-Hackathon): default branch development.
- [Judge quickstart](JUDGE_QUICKSTART.md): supported/contradicted/abstention examples and useful author rewrite.
- [Implemented architecture](../architecture/ARCHITECTURE.md): runtime sequence, AI/deterministic boundaries and physical storage.
- [Service registry](../api/PROVIDERS.md) and [key onboarding](../operations/CREDENTIALS.md): actual integrations versus optional/unavailable sources.

The 6 October functional checkpoint has selected fresh live RAG and useful rewrite/References/copy evidence, not a measured general scholarly accuracy claim. Report IDs are session-owned, not public sharing links. Judges should create their own reviews.

## Submission and evaluation evidence

The [submission readiness](SUBMISSION_READINESS.md) is the current requirement-to-evidence checklist, official-rule links, release identity, final-stage rubric mapping, video outline and prioritized owner actions. It explicitly retains rights/source approval, qualified evaluation, original dated baseline, final presentation/video and portal receipt gaps.

Use the [live receipt](https://github.com/smaq777/Basira-Hackathon/issues/169#issuecomment-6022396451) and [six-case acceptance](../evidence/2026-10-06-staging-1.14-acceptance.md), not a UI mock or green build as deployment proof. Full expert publication→future retrieval→consented email acceptance remains a separate task.

Prepared, reviewed, merged, deployed, submitted and accepted are different states. This guide does not certify eligibility or scholarly approval.

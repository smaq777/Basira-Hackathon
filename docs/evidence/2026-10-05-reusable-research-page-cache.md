# Reusable public research page cache

Implemented on the existing isolated Neon research branch `br-wandering-unit-b24xqw5d`, database `basirah_research`, with additive migration 0010. Production was untouched. The frozen versioned source corpus remains 62 passages; acquired public pages live in a separate reusable research table, not a silently changed corpus version.

`ResearchPageCache.store` accepts only validated, hash-matching, policy-eligible pending public snapshots. A small model labels the public original with typed topics; it receives no private draft, claim, review identity, or search query. Classification records model, prompt version, and request/response hashes. Machine topics are retrieval aids and do not grant authenticity, rights, or scholarly approval.

Cache identity includes exact URL, original hash, and policy hash. Original text, source attribution, and machine-label record are immutable. A changed original creates a separate version. A fresh acquisition of the same original can refresh only verification time and expiry; revoked rows cannot be resurrected by the writer. Default TTL is 30 days, bounded and configurable. Search and exact restoration require current policy, unexpired/unrevoked status, current URL eligibility, and a recomputed original hash. A policy change deliberately excludes old-policy entries until revalidated acquisition.

The cache searches lexical originals and optional compatible 1,536-dimensional embeddings. Document embedding input is explicitly bounded to 3,000 characters: title/topics plus an original head/tail view. The full original remains unchanged. View method, input hash, dimensions, model, and incomplete semantic coverage are recorded. Embedding outages preserve lexical search and allow classified originals to be stored without fake vectors; a later vector upgrade for such immutable entries is not implemented.

Shared cache provenance uses an allowlist and excludes private query hashes, gap reason, claim/review/revision identity, and context supplied by a private review. Report-specific query bindings belong in the individual report. Web policy eligibility and research-cache storage remain separate from source approval; all cached pages remain pending and research-only with rights unresolved.

The dedicated `basirah_page_cache_writer` login has no inheritance, bypass RLS, administrative privileges, or canonical-corpus writes. Its role can select/insert cache records and update only verification/expiry columns. The existing research reader receives SELECT only on this new table; production runtime receives no cache grants. The owning external `.env` contains `BASIRAH_WEB_CACHE_DATABASE_URL`; no credential value is committed. Transactions set a five-second statement timeout and check cancellation before commit.

## Actual isolated validation

Two already fetched eligible Firecrawl public originals were classified through the actual `createPageTopicClassifier` OpenRouter Luna callback and embedded through the actual compatible embedding adapter. These are [parental obedience](https://binbaz.org.sa/fatwas/8881/الضابط-في-طاعة-الوالدين) and [parental duties](https://binbaz.org.sa/fatwas/8880/ما-جاء-في-الكتاب-والسنة-في-فضل-بر-الوالدين) pages; their full originals remain external and in research storage. No synthetic test text was inserted into the durable cache.

Persisted topics were `family, ethics` and `family, ethics, quran_exegesis, hadith_studies`. A new cache instance retrieved/restored both originals; repeat storage skipped reclassification and document embedding. Compatible dense search and lexical retrieval during an embedding outage passed. Exact original hashes, topic provenance, bounded embedding views, policy identity, and source URLs are in external `AI_Foundation/experiments/research-page-cache-2026-10-05/VALIDATION.json`.

Rollback-only SQL probes rejected original mutation, hid expired records from the reader, permitted fresh verification/expiry refresh, hid revoked records, and denied writer revocation removal. Temporary owner role membership used for these probes was rolled back. The two public records remain reusable, and the frozen 62-passage corpus is unchanged. The official migrator applied 0010, with provisioning metadata and log retained externally. One initial audit stopped at an owner SET ROLE permission check after the real records were successfully written; the completed replay reused them instead of reclassifying or re-embedding them.

Eight targeted default tests cover idempotency, versioned originals, eligibility/hash failure, restored original integrity, expired/revoked exclusion, fresh expiry refresh, embedding outage and bounded view, cancellation after insertion without commit, and slow embedding fallback. Query embeddings have a separate 1.5-second budget so lexical lookup can still run within the optional cache-search budget; external cancellation remains terminal. Paid providers are absent from these tests. Runtime retrieval integration and paired before/after report evidence are separate from this repository module and database validation; this document does not claim a scholarly quality gain.

# Basirah interface references

These owner-approved Arabic screenshots are the visual source of truth for the scoped public review journey in Issue #25. They are design references, not evidence that a religious claim was verified, a provider call ran, or a deployment succeeded.

## Public journey

1. `screen-01-home.jpg` — guest text composer and product scope.
2. `screen-02-automatic-analysis-reference.jpg` — review-input layout reference.
3. `screen-03-result.jpg` — evidence-linked result and bounded editorial revision.
4. `screen-04-unresolved-voice.jpg` — unresolved result with an evidence-bound voice drawer.
5. `screen-05-ticket.jpg` — optional follow-up and ticket confirmation.

The manual phrase-type dropdowns visible in `screen-02-automatic-analysis-reference.jpg` are intentionally superseded by the owner's product decision. The implementation sends the submitted text directly into an automatic background-analysis state; users do not classify extracted phrases themselves.

## Reviewer workspace

The reviewer dashboard, queue, case detail and source registry extend the same typography, spacing, color and status language into a simple sidebar layout. All current reviewer records and counts are explicitly labelled as dummy data. No account, retained-history or unrestricted chat feature is implied.

## Interaction requirements

- Arabic-first RTL layout with responsive desktop and mobile behavior.
- Clear loading, empty, validation, recoverable error and success states.
- Motion that clarifies progress and navigation, with reduced-motion support.
- Separate quotation accuracy from inference support.
- Keep source text and model-generated editorial explanation visually distinct.
